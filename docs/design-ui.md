# 勇者へっぽこの小さな冒険 — 画面・操作・見た目の設計書(design-ui.md)

対象: 実装する人(プログラムに落とす精度で書く)。企画の土台は `docs/brief.md`。
書き方の約束: 数字は **論理サイズ 390 × 780** の px。色は `#rrggbb`。タイル座標は `(列x, 行y)`、左上が `(0,0)`。

---

## 0. 土台の決まり(全画面共通)

### 0-1. 画面の入れ物
```
実機の画面(例 iPhone 390×844)             実機が短い(例 iPhone SE 375×667)
┌──────────────────┐                       ┌────────────────┐
│   黒帯 (#0b0816)  │ ← 上下に余白           │▓│            │▓│ ← 左右に余白
├──────────────────┤                       │▓│  論理画面   │▓│
│                  │                       │▓│  390×780 を │▓│
│  論理画面 390×780 │                       │▓│  0.855 倍   │▓│
│  幅いっぱいに拡縮 │                       │▓│            │▓│
│                  │                       │▓│            │▓│
├──────────────────┤                       └────────────────┘
│   黒帯            │
└──────────────────┘
```
- 拡縮率 `SC = min(実幅/390, 実高/780)`。canvas は `ctx.setTransform(SC,0,0,SC, OX*SC, OY*SC)`(OX/OY は中央寄せの余白)。
- DOM(メニュー・会話)も同じ率で合わせる: `#ui { width:390px; height:780px; transform: scale(SC); transform-origin: 0 0; position:fixed; left:OXpx; top:OYpx }`。**canvas と DOM の座標系を 1 つにそろえる**(タップ位置の変換が 1 か所で済む)。
- タップ座標 → 論理座標: `lx = (clientX - OX) / SC`, `ly = (clientY - OY) / SC`。
- `devicePixelRatio` は 2 まで(`Math.min(dpr, 2)`)。obaa と同じ。
- safe-area: 上下の黒帯がそのまま安全余白になる。黒帯が出ない比率(2.0 ちょうど)の端末では、下のボタン列を `env(safe-area-inset-bottom)` ぶん持ち上げる。

### 0-2. 縦の基本配分(町・ボス戦・メニューで共通の帯)
```
y=0   ┌────────────────────────────────┐
      │ 上の帯 HUD(高さ 52)             │  所持金・場所名・設定ボタン
y=52  ├────────────────────────────────┤
      │                                │
      │  主画面(高さ 576 = 18 タイル)   │  町マップ / ボス戦 / 一覧
      │                                │
y=628 ├────────────────────────────────┤
      │ 下の帯 ボタン列(高さ 152)        │  そうび・なかま・もちもの・セーブ
y=780 └────────────────────────────────┘
```
- 主画面 576px は **32px タイル × 18 行**。横は 390 ÷ 32 = 12.19 タイル → 12 タイル + 両端 3px の半端(端は 1 列ぶん多く描いてはみ出しを隠す)。

### 0-3. 字の大きさ(最低値。これより小さくしない)
| 用途 | 大きさ | 太さ |
|---|---|---|
| 本文・会話 | 20px(字の大きさ「大」では 24px) | 700 |
| 補足・値段・説明 | 17px(「大」では 20px) | 700 |
| ボタンの字 | 18px 以上 | 900 |
| 見出し | 26px | 900 |
| 所持金 | 22px、`font-variant-numeric: tabular-nums` | 900 |
- 書体: obaa と同じ `"Hiragino Sans","Hiragino Kaku Gothic ProN","Yu Gothic UI","Meiryo","Noto Sans JP",system-ui,sans-serif`。絵文字は `"Apple Color Emoji","Segoe UI Emoji","Noto Color Emoji"`。
- 行間 1.6。1 行は **全角 15 字まで**(390px − 左右余白 32px − 窓の余白 32px = 326px ÷ 20px ≒ 16 字)。長い文は実装側で 15 字で折る(禁則は気にしない。句読点が行頭でもよい)。

### 0-4. ボタンの決まり
- 当たり判定は **56 × 56px 以上**。見た目が小さくても `padding` や透明な外枠で 56 を確保。
- 押した感じ: `box-shadow: 0 5px 0 #1b1430` → 押下中 `translateY(4px)` + `box-shadow: 0 1px 0`。obaa と同じ。
- 角丸 16px、縁 3px `#1b1430`。
- 文字色は背景が明るいとき `#1b1430`、暗いとき `#ffffff`。
- **連打対策**: 画面遷移を起こすボタンは押した瞬間に `disabled` にして 350ms 後に戻す。

## 3. 操作

### 3-1. タップで歩く(基本)
1. マップ上をタップ → 論理座標 → タイル `(tx, ty)`。
2. 通れないタイルなら、**その隣の通れるタイルのうち主人公に一番近い物**を目標にする(木や壁をタップしても、そこへ寄っていく)。扉・人のタイルは「目標=そのタイル(扉)/その手前(人)」。
3. BFS で経路(マップは 24×24=576 マスだけなので毎回全部探して問題なし)。斜めは無し。
4. 目標タイルに **黄色い輪 `#ffe066`(半径 12、太さ 3)** を置き、着くまで点滅。歩いている途中で別の所をタップしたら目標を差し替える。
5. 着いたら: 扉 → 自動で入る。人 → 自動で話しかける(向きを合わせる)。出口 → 確認。
6. 道が無い(池の中など)ときは主人公の頭上に「❓」を 0.6 秒。音 `nope`。

### 3-2. 十字キー(任意)
- 設定(⚙️)で ON/OFF。既定は **OFF**(タップ歩きが主)。初回起動時の案内で「歩きにくいときは ⚙️ から十字キーを出せます」と 1 回だけ言う。
- 位置: 右下、マップの上に重ねる。3×3 の格子、1 マス **56×56**、全体 168×168、`x=212〜380, y=450〜618`。真ん中は空。
- 見た目: 各キー `rgba(255,255,255,.35)`、縁 2px `rgba(27,20,48,.6)`、矢印 ▲▼◀▶ 22px `#1b1430`。押下中 `rgba(255,224,102,.8)`。
- 押しっぱなしで連続移動。`pointerdown/pointerup/pointercancel` で管理(`touchmove` で指がはずれたら止める)。
- 十字キー ON の間、その 168×168 の領域ではタップ歩きを無効にする。

### 8-2. 大魔王の HP バー(「桁外れ」の見せ方)
```
 HP ████████████████████████████████░░░░░░░░  9兆2,000億
     ↑ 7 重の層: 残り HP に応じて色が 7 段階で剥がれていく(ドラクエの桁感ではなく「層」で見せる)
```
- バー: `x=120〜382`(幅 262)、高さ 16、角丸 8、縁 2px `#fff`。
- HP の **最大値は桁外れ**(例 9,200,000,000,000)。1 本のバーだと最後まで減らないので **層の色**で見せる:
  7 層の色(外から): `#8a2be2` 紫 → `#4a148c` 濃紫 → `#1565c0` 青 → `#2e7d32` 緑 → `#f9a825` 黄 → `#ef6c00` 橙 → `#c62828` 赤。
  `残り割合 p` に対し `層番号 = floor(p*7)`、その層のバーを `(p*7 − 層番号)` の幅で描き、その下に次の層を全幅で敷く。→ 1 層削るごとに **色が変わって「1 枚剥がした」感**が出る。
- 数字: 日本式の **万・億・兆** で短く(`9兆2,000億`、17px、`#fff`、tabular)。1 桁減るごとにガタンと字を揺らす。

### 10-2. 昼の町の色(マップの印象)
- 草 `#7ec850` を面の 6 割に。道 `#d9b36b` と石畳 `#b9b4a8` が 2 割。屋根の赤 `#c0392b`・青 `#2f6fb0`・城の紫 `#6c4fb0` が差し色。

### 10-3. ボス戦の色
- 背景 `#1a0b2e` → `#3a1050`(縦グラデ)。黒い円 `#0b0816`。オーラ `rgba(138,43,226,.35)`。
- 文字は白 `#fff`、強調は `#ffe066`、ボスのセリフは `#ffb3c7`。

### 10-4. 文字の縁取り(canvas)
- obaa の `txt()` と同じ: `lineJoin='round'`、`lineWidth = max(3, size/5)`、`strokeText` → `fillText`。縁は `ink`、暗い背景で白文字でも縁は `ink`(白地の札では縁なし)。
- DOM の文字は縁取りしない。読みやすさ優先で **背景を暗い半透明の窓**にする。

### 10-5. 絵文字の描き方の注意
- **アトラス**(obaa の `ATL` をそのまま使う): 112px のセルに 92px で描き、`drawImage` で切り出す。毎フレーム `fillText` で絵文字を描かない(遅い・メモリが膨らむ・白紙化)。
- タイルの絵文字(花・看板・木の上の実など)は **マップの裏 canvas に 1 回描くだけ**なのでアトラス不要。人・仲間・演出の絵文字はアトラス経由。
- **`setTransform` のかけ直し**: `resize()`・`contextrestored`・`visibilitychange`・`pageshow` で必ず `ctx.setTransform(SC,0,0,SC,OX*SC,OY*SC)` を呼び直し、アトラスも `atlasReset()`。画面ゆれで `translate` を使ったら **フレームの最初に `setTransform` で戻す**(`save/restore` の取り忘れ対策)。
- 絵文字は **左右反転できない**(`scale(-1,1)` すると文字が鏡文字になる物がある。🏹 や ✍️ など)。向きは別の印(足元の三角)で見せる。
- 大きさ: アトラスの元が 92px なので、**190px に拡大すると少しぼやける**。お披露目のマント(190px)とボス(180px)は、**専用の大きいアトラス(セル 256px、元 220px、4×4=16 個だけ)**をもう 1 枚持つ。
- iPhone と Android で絵文字の形・幅がちがう(👩‍🦱 などの結合絵文字は Android で 2 文字ぶんの幅になることがある)。**中心を `textAlign='center'` で取り、幅に依存する配置をしない**。結合絵文字は `[...str]` ではなく、そのまま 1 つの文字列で描く。
- 絵文字が出ない環境(古い端末)のために、主人公と大魔王だけは **図形だけの代替**(丸い顔+点の目)を用意して、`measureText('🧒').width < 10` なら切り替える。

### 12-2. BGM(`bgmTick()` で 16 ステップ × 4 小節のループ。曲ごとに表を差し替える)

| ボス戦 | 0.105 秒(≒143 BPM) | 短調、`[0,3,5,7,10,12]` | `[0, −4, −2, −5]`(obaa のボスと同じ) | 低いベースを毎ステップ刻む。4 小節目にだけ高音を 2 オクターブ上で鳴らす(緊張) | sawtooth ベース 0.09 / square メロ / 1 拍目に sine 60Hz の低いドン |
| ピンチ(ボス戦 HP25% 以下) | 0.095 秒 | 同上 | 同上 | ベースを半音上げる(`+1`)、ドンを毎拍に | 同上 + `pinch` 重ね |
| 勝利ファンファーレ(1 回だけ) | 0.11 秒 | 長調 | 固定 | `C5 E5 G5 C6 (休) G5 C6 ×2`、半音で `[0,4,7,12,-,7,12,12]`、最後の 12 を 0.6 秒伸ばす。その後 町 BGM へ | square 3 本(0, +4, +7 の和音)|

| タイトル / オープニング | 0.2 秒 | 長調、`[0,4,7,12]` | `[0, −3, 5, 7]` | 4 ステップに 1 音のアルペジオだけ(静か)。オープニングは背景が明るくなるにつれ音量 0.3 → 0.6 | sine、リバーブ代わりに同じ音を 0.12 秒遅らせて小さく重ねる |
- ルート音は 110Hz(A2)基準 `110 * 2^((key+prog)/12)`。町は key=+3(C 長調に近い)、ボスは key=−2。

## 14. 実装者がやりがちな失敗 10 個

1. **canvas と DOM の座標がずれる** — 片方だけ `scale` して、タップ位置が合わない。両方に同じ `SC/OX/OY` を使い、変換関数を 1 つにする(0-1)。
2. **絵文字を毎フレーム `fillText`** — 100 体の町の人や紙吹雪 40 個で iPhone がカクつく・白紙になる。必ずアトラス(10-5)。大きい絵文字は専用アトラス。
3. **`setTransform` を戻し忘れる** — 画面ゆれの `translate` が積み重なって絵が画面外に飛ぶ。フレーム頭で `setTransform`、`save/restore` を対にする。
4. **絵文字を `scale(-1,1)` で左右反転** — 鏡文字になる物がある。向きは足元の三角で(2-4)。
5. **タップした所が壁だと何も起きない** — 「隣の通れる所へ寄る」をやらないと、年配の人は「壊れた」と思う(3-1 の 2)。
6. **会話の送りが速すぎる / 1 回のタップで 2 文飛ぶ** — `pointerdown` と `click` の両方で送っている。1 つにして、文字が出終わってから 120ms は無視(11)。
7. **お金の計算を画面ごとにバラバラに書く** — 残高がマイナスになる・表示が合わない。`pay(n)` 1 か所(11)。表示は `fmtG()` 1 か所(5-2)。
8. **装備の人形を部位ごとに別の座標系で描く** — ポーズを付けた瞬間にバラバラになる。肩・腰・首の **原点を決めて `rotate`**、子パーツ(武器・指輪)は腕の変換の中で描く(7-2、9-3)。
9. **大魔王の HP を 1 本のバーで** — 最後まで減って見えず、プレイヤーが「効いていない」と思って止める。層ではがす(8-2)+ 数字 + 剥がれる瞬間の演出。
10. **写真の保存で画面の canvas をそのまま `toBlob`** — 解像度が端末次第でにじむ・HUD が写り込む。1080×1350 の別 canvas に 3 倍で描き直す(9-4)。`navigator.share` が無い環境の逃げ道(長押し保存)も用意。

(おまけ 11) **iPhone の音が鳴らない** — ユーザーのタップより前に `AudioContext` を作っている。タイトルの最初のタップで `auInit()`。
(おまけ 12) **横幅 390 ぴったりで設計して、375 の iPhone で下のボタンが切れる** — 拡縮は `min(幅, 高さ)` 比で、下の帯は常に 780 の中に収める。iphone-check スキルで確かめる。
